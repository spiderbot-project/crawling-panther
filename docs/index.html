Power and signal

Eight servos draw far more current than the Arduino can supply, so they run from their own battery through a regulator and a switch. The Arduino only sends the control signals. Both supplies share a common ground.

Software

Calibration

Servo horns never sit at exactly the same angle, so 90° is a different pose on every leg. We calibrated each servo by hand:

  1. Power the servos from the battery and send each one a test angle.
  2. Adjust until the leg stands neutral: hip pointing straight out, knee at its resting height.
  3. Write that angle into the neutral table shown in the servo map.
  4. Describe every movement as an offset from the neutral angle, never as an absolute angle.

Trot gait

The legs move as two diagonal pairs, R1 + L2 and R2 + L1. While one pair steps, the other stays on the ground and pushes the body forward. The hips swing 20° and the knees lift 45°. Every move is split into 20 small sub-steps so the servos glide instead of jumping.

One full step is six moves:

  1. Lift the knees of R3 and L4.
  2. Swing R1 and L2 forward, and R2 and L1 back.
  3. Lower the knees of R3 and L4.
  4. Lift the knees of R4 and L3.
  5. Swing R2 and L1 forward, and R1 and L2 back.
  6. Lower the knees of R4 and L3.

The test routine does five steps forward, rests in the neutral pose, then does five steps backward.

The sketch

The sign array compensates for how each servo is mounted, since the left side is mirrored.

#include <Servo.h>

enum { R1, R2, R3, R4, L1, L2, L3, L4, N };

const int pins[N]    = {4,   6,   5,   7,  8,   10, 9,  11};
const int neutral[N] = {85, 110, 170, 30, 110, 40, 70, 145};  // calibrated angles
const int sign[N]    = {1,   1,  -1,   1, -1,  -1,  1,  -1};  // mounting direction

const int HIP_SWING     = 20;
const int KNEE_LIFT     = 45;
const int STEPS         = 5;    // steps forward, then backward
const int INTERP_STEPS  = 20;   // sub-steps per movement
const int STEP_DELAY    = 12;   // ms between sub-steps

// If the robot walks backward instead of forward, swap these two values
const int FORWARD  =  1;
const int BACKWARD = -1;

Servo servos[N];
int cur[N];      // current angles
int target[N];   // target angles
int moveDir = FORWARD;

// Move all servos smoothly from cur[] to target[]
void apply() {
  int start[N];
  for (int i = 0; i < N; i++) start[i] = cur[i];
  for (int s = 1; s <= INTERP_STEPS; s++) {
    for (int i = 0; i < N; i++) {
      cur[i] = start[i] + (long)(target[i] - start[i]) * s / INTERP_STEPS;
      servos[i].write(cur[i]);
    }
    delay(STEP_DELAY);
  }
}

void hip(int i, int d) {
  target[i] = neutral[i] + sign[i] * HIP_SWING * d * moveDir;
}

void knee(int i, bool lifted) {
  target[i] = neutral[i] + (lifted ? sign[i] * KNEE_LIFT : 0);
}

// One full step: both diagonal groups move once
void gaitStep() {
  // Group R1+L2
  knee(R3, true); knee(L4, true); apply();                              // lift
  hip(R1, +1); hip(L2, +1); hip(R2, -1); hip(L1, -1); apply();           // swing
  knee(R3, false); knee(L4, false); apply();                           // lower

  // Group R2+L1
  knee(R4, true); knee(L3, true); apply();
  hip(R2, +1); hip(L1, +1); hip(R1, -1); hip(L2, -1); apply();
  knee(R4, false); knee(L3, false); apply();
}

void rest() {
  for (int i = 0; i < N; i++) target[i] = neutral[i];
  apply();
}

void setup() {
  for (int i = 0; i < N; i++) {
    cur[i] = target[i] = neutral[i];
    servos[i].write(cur[i]);
    servos[i].attach(pins[i]);
    delay(500);   // start servos one by one (protects the regulator)
  }
  delay(2000);    // wait 2 s before walking
}

void loop() {
  moveDir = FORWARD;
  for (int k = 0; k < STEPS; k++) gaitStep();
  rest();
  delay(1000);

  moveDir = BACKWARD;
  for (int k = 0; k < STEPS; k++) gaitStep();
  rest();
  delay(1000);
}

Simulation Work in progress

We want the robot to find its own way of walking in simulation, then compare that with our hand-written trot gait. The stack is Python and MuJoCo for the physics, and PPO from stable-baselines3 for reinforcement learning.

  1. Build the MuJoCo modelIn progress. The link and leg lengths are not measured yet, so the model can't be finished.
  2. Replay the trot gaitCheck that the hand-coded gait looks right in simulation.
  3. Train with PPOLet the agent learn to walk, then compare it with the trot gait.
  4. Transfer to the real robotRun the learned walking on the hardware.

Challenges

What went wrong, and what we know so far.

Regulator protection

The voltage regulator went into protection and blinked when all 8 servos started at once. We now start the servos one at a time in code, and added a power switch and a capacitor.

Fixed

Servo on pin 11

This servo (L4) sometimes does not respond. We suspect a power drop or a loose connector, but haven't confirmed it.

Open

Limited torque

The MG90S has little torque for a 318 g robot, so the gait needs careful tuning of angles and timing. Small changes decide whether a step lifts the body or stalls.
